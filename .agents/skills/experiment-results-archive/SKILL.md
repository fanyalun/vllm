# 实验结果分类归档

交付实际可浏览的目录、汇总报告和来源映射，不只给整理建议。适用于新结果入库、历史目录迁移、指标补录与清理。用户指定范围、分类和指标优先；本 skill 不重新安排实验或更改测量协议。

## 先恢复实验身份

- 读取现有总索引、contract/config、manifest、completion marker 和代表性结果文件；盘点 Git 状态及已有归档规则。不要凭目录名、文件时间或脚本当前默认值认定实验配置。
- 从实际运行配置、命令、日志和冻结源码确认优化组合、模型/checkpoint、参数、测量范围、版本和完成情况。缺失信息标为 `unknown`，冲突列为待核实，不猜测补齐。
- 区分实验系列、配置来源、重复运行和正式请求；不能把拆出的 CSV 行数或配置来源数叫作独立实验数。
- 同一矩阵可有完整与未完成配置。完成标记须与预期配置覆盖、输出行数和有效测量相互印证；任务启动或等待 GPU 不算完成。

## 分类和存放

迁移或新增结果前阅读 [目录与记录约定](references/layout_and_records.md)。在已有归档中保持原命名和稳定 ID，不为统一外观重排无关实验。

默认 Pre-Verify 分类是 `01_moe`、`02_gdn`、`03_early_exit`、`04_execution`；基线和方法对比放 `00_baselines`。其他项目按研究问题调整类别，勿强行套用 MoE 分类。

组合实验按主要研究问题选一个主分类，完整优化组合写入路径和结构化字段，其他类别通过索引关联，不复制原始数据。路径使用“类别 / 优化组合 / 模型 / 参数配置 / 运行”，同配置的不同版本或重复测量保留独立运行目录。

每次归档都实际更新根索引、类别入口、配置索引、相应实验报告和来源映射。原始多配置文件只保留一份，通过 selector、原始行号与 SHA-256 定位各配置。相对符号链接可维持历史入口，但应检查目标有效且不会形成循环。

## 汇总指标和证据

阅读 [指标、清理与发布约定](references/metrics_and_retention.md)，按用户所需指标生成表格。报告必须能回答：测了什么、相对哪个对照、指标分母是什么、结论由哪些原始记录支持、哪些结论尚未验证。

- 分开列在线完整生成、固定输入 forward、kernel、离线模拟、诊断及正确性结果。不要汇成混合速度排名。
- 同配置只因数字相近不能去重；不同 seed、重复编号、模型版本、采样参数或 GPU 条件可能是有效重复。
- 负收益或低接受率是有效实验结论；进程失败、协议错误和未完成运行另标状态，不能混进正式汇总。
- 用户要求重跑时保留原实验身份，新增运行并更新主报告；固定会影响语义的旧配置并记录实际生效值。旧结果保留来源关系，避免静默覆盖。归档请求本身不构成重跑授权。

## 迁移、清理和校验

先建立 old→new 计划、字节数和内容 hash，再逐批迁移。目标存在时先比较内容和身份，不覆盖。保留原始证据内部的历史路径，通过映射解释，不批量改写原始日志和 JSON。

删除仅限当前任务明确授权的范围；先核实可保留的证据并写清理清单，再删除。既有删除授权足够时不重复询问；此 skill 和过去其他任务的删除授权不构成本次授权。

完成后验证并记录：

- 保留源文件迁移前后 SHA-256 一致；生成报告单独记录为派生产物。
- 每个配置的 selector/行号仍命中原记录，汇总计数和关键公式可由原始数据复算。
- 所有本次涉及的 Markdown 链接和符号链接可解析；目录、配置和运行覆盖数与索引一致。
- 新增运行不重复入库，重复执行归档不会复制同一来源或重命名已有稳定运行。
- 缺口、失败的校验和明确丢弃的信息在报告可见；部分通过不写成全部通过。

将结果写入 `.archive/validation.json`；已有历史审计保持其时间和范围，新批次追加独立记录。输出目录入口、主要分类、保留/删除数量与字节、验证结果及 Git 发布状态。除非本任务有发布授权或适用的仓库要求，否则不自行提交或推送。
