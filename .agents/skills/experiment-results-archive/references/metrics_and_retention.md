# 指标、清理与发布约定

## 指标不能只保留一个小数

接受率记录 accepted、proposed 以及两者含义。区分 MTP→Pre-Verify 内层和 Pre-Verify→Target 外层，以及独立 Draft→Target。部分旧实现使用 scheduled 而非 proposed 作为分母，必须原样解释，不强行统一。

平均接受长度若含 bonus，可用 `1 + accepted / verify_steps`；先核实原计数协议，不能对所有来源机械套用。说明是否包括末次输出上限截断前的 verify 接受计数，以及内层是否包括最后未被 Target 消费的 proposal。拒绝伪造计数以对齐返回长度。

专家统计保留 retained edges、native edges、token-layer rows 和 zero-expert rows。跳过率为 `1 - retained_edges / native_edges`；原生 top8 的分母通常是 `8 × rows`，不是模型全部专家数。专家 union 保留预算 60% 不等于 token 专家跳过 40%。说明 anchor、draft 位置、层和 warmup 的覆盖。

吞吐区分返回 token 总量/完整 wall-clock 与逐轮或逐请求均值/中位数；pooled 吞吐不能替代旧报告的中位数。固定输入 kernel 加速不代表端到端收益。百分比相对变化与百分点变化分别标注。

parity、任务正确率和接受率分开。AR 自身重复不一致时明示这一限制；kernel 容差通过或高接受率不能证明 lossless。只测 4 个样本就写明样本范围，不外推普遍结论。

m10 的历史教训：脚本默认停止策略和专家权重模式曾发生变化。归档时以原运行实际配置/源码为证，后续重跑需显式固定语义参数并验证引擎生效值；不能只照抄旧命令并称为同协议。

## 清理规则

| 类型 | 判断与处理 |
| --- | --- |
| 完成且协议有效、收益为负 | 保留正式结果、配置和限制，不当作“失败垃圾” |
| 崩溃/不完整/协议错误 | 与正式结果隔离；经授权可删除大日志，保留原因、配置及必要诊断证据 |
| 正式运行前的 smoke/warmup | 确认不含唯一验证证据，再按授权清理；保留轻量验证结论 |
| 重复文件 | 内容 hash 和实验身份一致、有完整 canonical 副本才去重；有效统计重复运行不删 |
| profiler/Nsight 大文件 | 若授权且原始事件不再需要，先保留足够聚合与配置；删除后注明逐事件/相关性分析不可恢复 |
| 数据集、真实输入张量、正式输出 | 不能仅因文件大而认定无用；有复现、重分析价值的留在本地 |

清理清单记录路径、hash、bytes、原因、保留证据位置和执行状态。压缩与删除分别统计，不把压缩前大小当实际释放量。删去原始证据后的聚合仍可报告，但不能称原始证据完整。

## Git 发布

本地归档完整性与 Git 收录是两回事。发布授权存在时，先检查 remote、分支和 dirty 状态，仅暂存本任务代码及明确选择的轻量报告；不要 `git add -f benchmark_results` 整目录，也不修改无关 `.gitignore` 规则。

提交前检查暂存文件大小，推送前检查相对远端新增 blob 的总大小与最大对象；仓库已有历史大文件不代表本次应重传。可将 1 MiB 作为需要逐项检查的提示值，不是自动删除或拒绝发布阈值。大原始文件默认留本地；必要的其他发布方式由任务需求决定。

在 `/home/fanya/vllm`，既往遇到 sparse pack 重传历史大对象；该仓库推送优先使用 `git -c pack.useSparse=false push <remote> <branch>` 并检查新增对象范围。其他仓库按实际情况处理，不把此选项视为普遍要求。

依适用仓库规则运行必要检查；检查工具若只格式化生成报告，更新派生产物 hash，不改冻结原始证据。推送后核验远端 HEAD；失败则区分“本地提交完成”和“远端发布失败”。在发布包中说明原始测量仅在本地可用，不能把本地绝对链接当作远端可下载文件。
